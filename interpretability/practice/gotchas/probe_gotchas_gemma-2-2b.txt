ch.2  sets: the order you see is the hash table, not the insertion order

For ints the set's order is still deterministic (small ints hash to themselves); for strings it depends on a per-process seed, so the unseeded case is not scoreable at all.

ch.3  bound methods: a fresh object on every attribute access
========================================================================
    `o.f` builds a new bound-method object each time it is evaluated, so `o.f is o.f` is False while `C.f is C.f` is True and `o.f == o.f` is True. The id() pair is the deep end: id(o.f) == id(o.f) is True only because the first temporary is freed before the second is built and the allocator hands the address straight back -- let anything allocate in between and the same comparison is False. Allocator behaviour, not semantics; hence implementation_defined.

ch.4  comprehension scope: the answer changed in Python 3.12 (PEP 709)
========================================================================
    Up to 3.11 a comprehension ran in its own frame, so `locals()` inside it showed the hidden `.0` iterator argument. From 3.12 comprehensions are inlined into the enclosing function and `.0` is gone. The code is byte-for-byte identical; only the interpreter differs, and the prompt is the only place that says which one.
